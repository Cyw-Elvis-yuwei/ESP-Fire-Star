## 当前效果

Qt新增“持续通信测试（60秒）”。只发送GET_STATUS查询，发送间隔至少100ms，最多每秒10次，始终最多一条请求等待应答。界面显示进度、成功/总数、失败与超时。结束自动保存JSON/Markdown报告，逐条查询记录完整保存，包含成功率、实际频率及成功回复的最小/平均/P95/最大延迟。

正常回归与持续测试互斥；运行时手动控制和主动断开禁用，关闭窗口提示先完成或停止。停止后不再发送新查询，当前查询最多等到500ms超时后结算；提前停止记cancelled，即使成功率100%也不算完整通过。单条应答超时且设备仍在线时继续记录后续查询；设备离线、传输错误、日志故障或重启观察则结束并记录原因。

## 使用与边界

本阶段结束时已部署新版Ubuntu程序；重新启动须按当前接口状态连接can0。点击“持续通信测试（60秒）”即可亲自运行；可点“停止持续测试”提前结束。LED通常保持不动，因为本功能只查询状态。每轮在gui会话下独立continuous目录留档。

此次完整真机测试由助手使用QtTest操作真实控件，按用户授权的分工完成；没有把它记为用户亲自点击。原7步正常回归另有用户验收。

本结果证明在当前配置和约每秒10次查询下的一轮60秒通信表现，不能推出总线饱和负载、长时间可靠性或物理断线恢复。响应时间包含Linux/Qt/USB/适配器/固件链路，不是单纯CAN线上的传输耗时。后续受控恢复已单独完成，见[恢复报告](../recovery-run-2026-09-25/README.md)，不倒算为本轮持续测试覆盖。
