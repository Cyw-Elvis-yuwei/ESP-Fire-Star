## 实现与复用

Qt新增“一键真机正常回归”按钮，复用DiagnosticEngine原有的唯一在途命令、序号/操作匹配、超时和报文日志。NormalRun只编排7步：读取初始状态 → 关闭LED → 查询确认关闭 → 打开LED → 查询确认开启 → 恢复初始状态 → 查询确认已恢复。

每步应答通过后才继续，间隔400ms。正常结束恢复运行前通过查询得到的LED状态；异常或用户停止后不再继续发恢复命令，状态需重新查询。运行中禁用手动开关/查询及主动断开，关闭窗口提示先等完成或停止。每轮使用唯一子目录，result.json/result.md自动保存，不覆盖旧轮次。

真机按钮拒绝vcan。离线故障回归仍只允许vcan；没有放开原CLI限制，没有刷写固件、复位设备或改接线。报告只判定协议控制/查询，不自动声明软件看到了实物灯。

## 报告与运行方法

打开现有Ubuntu项目目录，真实can0已准备好时运行：

```bash
cd ~/can-diagnostic-bench/diagnostics
./build-app/can-diagnostic-bench --interface can0
```

看到“设备在线”后点“一键真机正常回归”。应出现7/7，报告自动保存在当前gui会话下的normal-日期-随机标识目录。可以重复点击，每轮独立留档。初始关时绿灯短暂亮起再熄灭；初始开时会先关闭再恢复开启。报告不会替代物理目视观察；已有用户点灯确认与DAP状态核对各自留档，不额外要求重复整轮操作。

本轮不包含持续查询或故障注入；后续已另行完成[持续查询](../continuous-run-2026-09-25/README.md)和[受控恢复](../recovery-run-2026-09-25/README.md)。Bootloader和升级未实现，不属于初版验收范围。
