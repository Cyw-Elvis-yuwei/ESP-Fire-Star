# 公开仓库复现指南

## 1. 目录与工具

仓库根目录即工程根目录，克隆到任意目录后在根目录操作。Linux开发环境见[首页](../README.md)，Qt/CLI/测试由`bash tools/build.sh`构建。标准项目不要求安装WSL，已有Linux或VMware Ubuntu即可。

STM32源码在`firmware/stm32-can`，build.ps1可用`-ArmCompiler`指定ARM Compiler5的bin目录。来源固定清单和第三方文件已经随仓库保留；编译器需自行合法安装。实际脚本不依赖CubeMX .ioc，也不等同原厂家uvprojx在Keil GUI中直接通过。

## 2. 物理连接

H对H、L对L、GND对板上J13 GND；J40短接供电，CANable启用120Ω。接线和电阻检查必须全断电。当前平台的两端终端实测59.4～59.5Ω。详情见[使用指南](使用与恢复指南.md)。真实固件默认上电LED关闭；先建立can0，再必要时复位解除缺少ACK造成的停发。

## 3. 发布版工具的设备选择

公开源码不内置原作者设备序列号。两个选择设置使用环境变量，仍保持“只操作明确指定的设备”原则：

```powershell
$env:CANBENCH_DAP_ID = '你实际核对的DAP探针ID'
```

```bash
export CANBENCH_CANABLE_SERIAL='你实际核对的CANable序列号'
bash tools/restore_can0.sh --check
# 协调好专项拔插验收后，才启动一次性助手：
sudo env CANBENCH_CANABLE_SERIAL="$CANBENCH_CANABLE_SERIAL" bash tools/restore_can0.sh --watch-replug
```

DAP未设置时使用不匹配的UNCONFIGURED_DAP哨兵，不能自动选择任意探针。USB脚本未设置串号会在设备查询/变更前退出。`--check`仅核对已经存在的can0和唯一slcand，不能首次创建接口。

烧录/复位工具仍要求自己的可信完整备份、同芯片身份及已审核产物。公开的脱敏验收文件只供阅读，不能拿来通过身份检查。`exercise_node_recovery.py`默认故意暂停约3秒并复位，`--reset-only`才是仅复位；都不是普通只读查询。不要直接照抄历史日志中的烧录指令。

## 4. 证据阅读

`artifacts`按原阶段保存公开副本；截图原像素保留。JSON/文本中的个人路径与设备标识经过脱敏，数值、布尔结果与协议内容保持；历史哈希与公开副本哈希不可混用。

7/7、574/574、故障恢复与用户灯反馈有独立证据。当前窗口截图只证明采集时真实心跳在线，不证明相机拍到了板子。完整目录见[画廊](真机证据画廊.md)。

主机适配测试在Windows执行`firmware/stm32-can/test-host.ps1`，默认使用PATH中的clang.exe；可传`-Clang`完整编译器路径。它只运行主机替身测试，不连接硬件。
